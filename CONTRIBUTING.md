# Для разработчиков

Спасибо, что хотите помочь. Здесь — как устроен проект, как его запустить из исходников и что проверить перед pull request.

## Окружение

Проект живёт на [uv](https://docs.astral.sh/uv/): он сам ставит нужный Python (3.10+) и зависимости из `uv.lock`. `requirements.txt` нет.

```bash
uv sync              # окружение с зависимостями для разработки (pytest, ruff, httpx)
uv run webui.py      # веб-интерфейс на http://127.0.0.1:8000
uv run pytest -q     # тесты
uv run ruff check .  # линтер
```

Полезные переменные окружения:

- `YADISK_NO_BROWSER=1` — не открывать браузер при запуске;
- `YADISK_PORT=8010` — второй экземпляр рядом с основным;
- `YADISK_DEMO=1` и адрес `/?demo=waiting` (а также `setup`, `downloading`, `done`, `token`, `disk_full` и другие) — любое состояние главного экрана без Яндекса.

## Как устроен проект

```
webui.py              запуск веб-интерфейса: собирает приложение FastAPI из webapp/
webapp/               сервер интерфейса по разделам:
  rescue.py           «Режим спасения»: Диск и Безлимит параллельно, отложенное — раундами
  rescue_view.py      сводка для Главной (/api/status.rescue) — чистые функции
  status.py           /api/status
  control.py          кнопки: запуск, повторы, настройки, папки, сортировка
  tasks.py            фоновые процессы (CLI-скрипты) по слотам и их журналы
  queue_db.py         счётчики и выбор «что качать» в state.db и unlim_state.db
  access.py, links.py, folders.py, logs.py, …  остальные разделы (список — в webapp/__init__.py)
webui_assets/
  app.html            каркас интерфейса
  static/             app.css и js/: core.js, components.js, screens/*.js (без сборки)

main.py               CLI обычного Диска: check / scan / download / verify / stats
downloader.py         обход Диска и скачивание через REST API
state.py              SQLite-состояние Диска (state.db)
storage_fetch.py      скачивание одного файла с серверов хранения, молчащие серверы
verify.py             проверка скачанного для Диска и безлимита: на месте ли файлы, размер, MD5

unlim_download.py     список безлимита (mpfs/list) по данным входа из браузера
unlim_worker.py       параллельное скачивание безлимита (unlim_state.db)
unlim_common.py       общий код безлимита: сессия, база, транзакции

public_download.py    скачивание по публичным ссылкам (links_state.db)
organize.py           сортировка по типам (по кнопке)
dedupe.py             поиск дубликатов по MD5
yandex_health.py      монитор состояния серверов Яндекса
supporters.py         «Нас поддерживают»: список с GitHub, без сети — копия из программы
utils.py              общие утилиты: пути, коды выхода, пределы

tools/
  sync_supporters.py  переносит донаты DonationAlerts в supporters.json (GitHub Actions)
tests/                pytest
docs/images/          скриншоты для README и инструкции
```

Веб-интерфейс запускает CLI-скрипты как отдельные процессы и читает их вывод. Поэтому:

- строки журналов вида `kind | текст` (`auth_expired`, `storage_down`, `local_disk` и другие), а также строки прогресса (`Найдено: N`, `Прогресс: …`) — это API между процессами: если меняете формулировку, меняйте и разбор в `webapp/` (`diagnostics.py`, `rescue.py`, `rescue_view.py`);
- процессам, которые запускает веб-интерфейс, выставлена переменная `YADISK_WEBUI=1` (`utils.under_webui()`): подсказки вида «запустите снова» и «--wait» печатаются только в консоли;
- коды выхода (`EXIT_*` в `utils.py`) значат одно и то же для всех скриптов: `1` часть файлов не скачалась, `2` ключ или данные входа не подходят, `3` Яндекс недоступен, `4` проблема с локальным диском, `5` скачано всё доступное, остальное ждёт серверов Яндекса;
- имена слотов задач и ключи `/api/status` читает интерфейс — их тоже нельзя переименовывать молча.

## Правила

- Тексты интерфейса, журналы, комментарии и документация — на русском. Пользователи программы — не программисты: пишите простыми словами, кнопки называйте действием («Удалить ключ», а не «Изменить»).
- Не показывайте имена файлов `*.md` как текст ссылок в интерфейсе: `.md` — доменная зона, Telegram и браузеры превращают такое имя в ссылку на несуществующий сайт. Инструкция в программе открывается по адресу `/guide`.
- Поведение только для Windows закрывайте проверкой `utils.IS_WINDOWS`; проверки путей должны проходить и на Windows, и на Linux.
- Тесты, которые пишут кириллицу в файлы, передают `encoding="utf-8"`: у GitHub Actions на Windows кодировка по умолчанию cp1252. `python -X warn_default_encoding -m pytest` покажет все такие места.
- Тесты не трогают настоящие `.env`, `cookies.json` и базы: `tests/conftest.py` подменяет пути в `webapp/paths.py` на временные. Новые файлы проекта добавляйте туда же. Модули `webapp` читают пути и настройки в момент вызова (`paths.DB_FILE`, `config.get_config()`), а не копируют при импорте, — иначе подмена в тестах до них не дойдёт.
- После правок интерфейса поднимите `APP_VERSION` в `utils.py`: версия в адресах файлов — единственный способ сбросить кеш браузера.
- `.bat`-файлы хранятся с окончаниями строк CRLF, иначе cmd.exe путает метки.
- Версия uv закреплена в `webui.bat`, `webui.sh` и `.github/workflows/ci.yml`. Обновляя её, поменяйте и SHA-256 установщиков: `uv-installer.ps1` в `webui.bat`, `uv-installer.sh` в `webui.sh` (файлы со страницы релиза uv на GitHub). Со старой суммой установка uv у новых пользователей остановится на проверке. `uv.lock` пересоберите той же версией: `uvx --from uv==<версия> uv lock`.

## Pull request

1. `uv run ruff check .` и `uv run pytest -q` проходят.
2. Если менялся интерфейс — приложите скриншот (подойдёт демо-режим) в светлой и тёмной теме.
3. Опишите, что меняется для пользователя, простыми словами.

CI (`.github/workflows/ci.yml`) запускает линтер и тесты на Windows, Linux и macOS с Python 3.10 и 3.13.

## Список «Нас поддерживают»

`supporters.json` обновляет GitHub Actions (`.github/workflows/supporters.yml`) раз в 15 минут: `tools/sync_supporters.py` забирает донаты через API DonationAlerts по ключу из секрета `DONATIONALERTS_TOKEN`. Ссылки и @упоминания из имён и сообщений вырезаются. Донат можно скрыть целиком (`hidden`) или скрыть только сообщение (`no_message`). Записи без `id` добавляются руками и не перезаписываются.
